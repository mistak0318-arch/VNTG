# 주문 기능 설계 — 승인 대기 (2026-08-27)

> **상태: 2026-09-03 밤 구현됨 (P1 골격).** 벤티지: "바로 구현해." 아래 설계 그대로 들어갔다 —
> `server/src/orders.ts` · `server/src/routes/order.ts` · `web/src/pages/OrderPage.tsx`.
>
> **아직 한 주도 안 나갔다.** `ORDERS_ENABLED` 와 주문 앱키가 없으면 라우트가 전부 404 이고 화면은
> 「꺼져 있다」 카드만 뜬다. 첫 주문은 벤티지가 모의 앱키를 넣은 뒤다 (5절).
>
> **설계에서 달라진 것 셋** — 이유와 함께:
> ① **정정(kt10002)을 안 만들었다.** 취소하고 다시 내면 같은 결과다. 주문이 나가는 길은 적을수록 좋다.
> ② **쾌속(프리셋) 탭을 안 만들었다.** 어차피 2단계 확인을 지나야 하므로 클릭 수가 줄지 않는다.
> ③ **거래소를 골라 낼 수 있게 했다** (KRX·NXT·통합 SOR). 벤티지 요청. 거래소별로 주문 접수 시간이
>    달라서 화면이 「열림/닫힘」을 상시 보여 주고, 서버도 그 창 밖이면 거절한다.
>
> **자동주문·예약주문·스탑로스는 조사 끝에 「불가능」이 아니라 「안 한다」로 남았다** — 1절 아래 표 참고.

## 0. 확정된 결정 (2026-08-27 대화)

| 결정 | 내용 |
|---|---|
| **소액 전용 계좌만** | 주문 기능은 별도로 만든 소액 계좌에만 물린다. 큰돈은 키움 정식 앱으로 — "증권사에서 안전하게 만든 앱이 있는데 굳이 쓸 필요 없지". 모든 벽이 뚫려도 피해가 그 계좌 잔고로 한정된다 |
| **모의투자 먼저** | 키움 REST 모의투자 도메인으로 전체 기능을 만들고 몇 주 실사용 → 가드레일 검증 후 실계좌 키로 전환 |
| **자동감시주문 제외** | 서버가 혼자 주문을 쏘는 구조는 위험 등급이 다르다. 「조건 도달 → 텔레그램 알림 + 화면의 원터치 주문 버튼」까지만 — 방아쇠는 항상 사람이 당긴다 |
| **구현 신호** | 사용자가 명시적으로 시작하라고 할 때까지 착수하지 않는다 |

## 1. 왜 위험한가 — 위협 모델

지금까지 최악의 사고 = 조회 데이터 유출. 주문이 붙으면 최악의 사고 = **남이(또는 버그가) 내 돈으로 주문.**

| # | 위협 | 경로 | 대응 (아래 3절) |
|---|---|---|---|
| T1 | 외부 침입 | Cloudflare Access 우회·설정 실수 → 서버 API 도달 (서버가 키움 토큰을 쥐고 있다) | 주문 비밀번호(L1) + 킬 스위치(L5) + 알림(L6) |
| T2 | XSS | 텔레그램·뉴스·공시 등 **남이 쓴 콘텐츠**를 렌더링 → 로그인된 브라우저에서 주문 API 호출 | 주문 비밀번호(L1) + 2단계 확인(L2) + 커스텀 헤더(L7) |
| T3 | CSRF | 다른 사이트에서 인증된 세션으로 POST | 커스텀 헤더 필수 + Origin 검사(L7) |
| T4 | 내 버그 | 재시도 루프·수량 단위 착각·더블클릭 중복 제출 | 가드레일(L3) + 멱등 토큰(L2) |
| T5 | 기기 분실 | 로그인된 폰/PC | 주문 세션 TTL 10분(L1) + 소액 계좌(L0) |
| T6 | 공급망 | npm 의존성 오염 | 소액 계좌(L0) + 알림(L6) — 완전 방어는 불가, 피해 한정으로 |

서버가 주문을 쏠 수 있으면, 서버에 난 버그와 서버에 든 침입자도 주문을 쏠 수 있다.
대신 **「조건 도달 → 알림 → 화면에서 사람이 주문」** 이 이미 있다(손절선 감시·슈퍼신호등·급변 시그널).

보드 연계: 관심종목·슈퍼신호등·호가창 어디서든 「주문」 버튼 → 주문 탭으로 종목 프리필 (연동과 같은 길).

### 2-2. 매매구분과 스톱지정가 — 2026-09-04 정정

09-03 에 「스탑로스·스톱지정가도 REST 에 없다」고 적었는데 **틀렸다.** 키움이 8/27 에 공개한 공식
저장소(`github.com/Kiwoom-Securities/Kiwoom-REST-API`)의 `examples/국내주식/주문/buy_domestic_stock.py`
에 `trde_tp` 코드표가 있다. **18개**다 — 우리는 0·3 둘만 쓰고 있었다.

|---|---|---|---|
| 0 | 보통(지정가) | 필수 | — |
| 3 | 시장가 | 안 씀 | — |
| **28** | **스톱지정가** | **필수** | **필수(발동가)** |

⚠️ **코드값과 이름은 공식 표지만, 「주문단가를 보내야 하나」는 추론이다.** 예제로 확인한 것은 0·3·28
뿐이다. 중간가(29~31)와 시간외(61·81)는 모의 실측에서 틀리면 `orders.ts` 의 `TRADE_TYPES` 한 줄만 고친다 —
화면은 이 표를 서버에서 받아 그리므로 따라온다.

**스톱지정가가 우리 원칙에 안 걸리는 이유.** 주문 한 번으로 발동가까지 같이 넘기므로 **우리 서버가
조건을 지켜보지 않는다.** 발동을 판단하는 쪽은 키움/거래소다. 설계가 0절에서 뺀 「자동감시주문」은
*우리 서버가* 시세를 보다 스스로 주문을 쏘는 구조를 말한다. `placeOrder` 의 유일한 호출자가
`executePrepared` 라는 성질은 그대로다.

**자를 둘 쓴다.** 손절 스톱은 현재가에서 멀리 두는 것이 정상이라 지정가와 같은 ±5% 를 물리면 기능이
죽는다. 그래서 `orderGuard.json` 에 `stopCollarPct`(기본 30)를 따로 뒀다.

* 발동가 ↔ 현재가 — `stopCollarPct` (넓게)
* 주문단가 ↔ 발동가 — `priceCollarPct` (좁게). 둘이 멀면 그건 오타다

**시간외 구분(61·62·81)은 정규장 시간창 검사를 건너뛴다.** 정규장 밖에 내는 것이 정상이기 때문이다.
시간외 창을 새로 박아 두지는 않았다 — 시간표는 2026-09-14 KRX 애프터시장 개편 때 한 번에 고치기로 한
자리라, 그때까지는 키움이 거절하게 둔다.

**손절선 감시와는 아직 안 엮었다.** 「손절선이 깨지면 자동으로 스톱주문」은 사람이 방아쇠를 당기지
않는 길이라 지금 구조에서 만들지 않는다. 손절선 알림을 보고 **화면에서 스톱주문을 거는** 것까지가 지금이다.

## 3. 보안 아키텍처 — 겹겹이 (한 겹이 뚫려도 다음 겹이 막는다)

### L0. 계좌 격리 (피해 상한)
- **소액 전용 계좌** 전용 앱키. `.env` 에 조회용 키와 **별도 키**로 저장 (`KIWOOM_ORDER_APP_KEY/SECRET`).
- 모의투자 단계에서는 모의 도메인 전용 키. 실전 전환은 `.env` 교체 + 명시적 재시작.

### L1. 주문 비밀번호 (인증 두 번째 겹)
- 별도 주문 비밀번호. 서버는 **해시만** 저장 (scrypt, salt 포함, `server/data/orderAuth.json` — git 제외).
- 입력 → 서버가 **주문 세션 토큰** 발급 (TTL 10분, 메모리 보관, 연장 없음 — 만료되면 다시 입력).
- 모든 `/api/order/*` 는 이 토큰 없이는 **404** (403 이 아니라 404 — 라우트 존재 자체를 숨긴다).
- 5회 연속 실패 시 30분 잠금 + 텔레그램 경보.

### L2. 2단계 주문 + 멱등성 (실수 방지)  ✅ 구현됨
1. `POST /api/order/prepare` — 종목·수량·가격·구분을 보내면 서버가 검증(가드레일) 후 **주문서 + 1회용 nonce** 반환 (유효 30초).
2. 화면이 주문서 내용(종목명·수량·금액·예상 수수료)을 **다시 보여주고** 확인 클릭.
3. `POST /api/order/execute` — nonce 로 실행. **nonce 는 1회용** — 더블클릭·재전송은 거부된다.

### L3. 서버 가드레일 (버그 보험 — 설정 파일로, 화면에서 못 고침)
`server/data/orderGuard.json` (기본값은 코드에, 파일은 수동 편집만):

| 항목 | 기본값 | 설명 |
|---|---|---|
| `maxOrderKrw` | 1,000,000 | 1회 주문 금액 상한 |
| `maxDailyKrw` | 3,000,000 | 1일 누적 주문 금액 상한 |
| `maxDailyCount` | 20 | 1일 주문 횟수 상한 |
| `priceCollarPct` | 5 | 지정가가 현재가 ±5% 밖이면 거부 |
| `marketHoursOnly` | true | 정규장(08:30~15:30 KST) 밖 거부 |
| `allowedCodes` | null | null=전체. 종목 화이트리스트를 걸 수도 있다 |

상한 초과는 **무조건 거부** — "경고 후 진행" 없음. 넘고 싶으면 파일을 직접 고치고 재시작.

### L4. 실행 경로 단일화
- 주문을 실제로 쏘는 함수는 서버에 **딱 하나** (`placeOrder()`), 모든 검증을 통과한 뒤에만 도달.
- 이 함수 안에서: 가드레일 재검증(방어적 이중 체크) → 키움 호출 → 결과 기록 → 알림. 다른 어떤 코드도 키움 주문 API 를 직접 부르지 않는다.

### L5. 킬 스위치
- `.env` `ORDERS_ENABLED=1` 일 때만 주문 라우터가 **등록**된다 (기본: 미등록 → 전부 404).
- 화면에도 비상 버튼: 「주문 기능 잠금」 — 누르면 서버가 메모리 플래그를 내려 재시작 전까지 전면 거부.

### L6. 감사 로그 + 즉시 알림 (마지막 방어선)
- 모든 주문 **시도**(prepare·execute·거부·실패 포함)를 `server/data/orderLog.json` 에 append-only 기록: 시각·종목·수량·가격·결과·거부 사유·요청 IP.
- execute 성공/실패는 **텔레그램 즉시 발송** (전용 갈래 또는 signal 방). 내가 안 낸 주문이 울리면 그 순간 안다.
- 체결확인 탭이 키움 체결 내역과 우리 로그를 **나란히** 보여준다 — 로그에 없는 체결 = 빨간 경고.

### L7. 웹 계층
- `/api/order/*` 는 POST 만 + 커스텀 헤더(`X-VNTG-Order`) 필수 + Origin/Referer 가 우리 도메인인지 검사 (단순 CSRF 차단).
- 주문 화면에는 남이 쓴 콘텐츠(뉴스·텔레그램)를 렌더링하지 않는다 — 주문 탭은 격리된 화면으로.
- Cloudflare Access 는 그대로 첫 겹으로 유지.

### UI 안전 장치
- 모의/실전을 **화면 전체 뱃지**로 상시 표시 (모의=파란 띠, 실전=빨간 띠). 어느 쪽인지 헷갈리는 순간이 사고다.
- 주문 폼에 오늘 남은 한도(금액·횟수) 상시 표시.
- 매수·매도 버튼 색 분리(빨강/파랑), 확인 다이얼로그에 **총액을 크게**.

### 체결 알림 (벤티지: "체결되면 알림 오는 구조까지")

주문이 접수되면 그 **주문번호만** 감시 목록에 올린다. 5초마다 ka10076 을 보고 체결량이 늘면:

  · **알림함(종)** — 출처 `order`, 급함 urgent, 누르면 그 종목 화면으로. 설정 › 알림에서 끌 수 있다
  · **텔레그램 order 방** — `[모의]/[실전]` 딱지와 함께

다 차거나 취소·거부면 감시를 접는다. **미체결이 하나도 없으면 타이머 자체가 안 돈다** — 조회 0회다.
5시간이 지난 주문도 접는다(장이 끝났는데 도는 것을 막는다).
