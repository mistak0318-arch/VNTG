# 📰 뉴스레터 기능 (2026-08-13 요청) — 텔레그램과 함께 최우선

인포스탁 주식신문 같은 형식의 리포트를 **하루 3회** 사용자 네이버 메일로 발송.

## ⚠ 먼저 확인할 것 — 인포스탁 크롤링은 하지 않는다

인포스탁은 **유료 구독 서비스**이고, 페이지에 이렇게 명시돼 있다:

> "본 주식신문은 인포스탁 유료회원에게 제공되는 정보이며, 본 컨텐츠를 캡쳐하여
> 온라인상에 게시하거나 공유하는 행위는 저작권법 위반으로 고발조치 됩니다."

따라서 **인포스탁 내용을 긁어와 재배포하는 방식은 구현하지 않는다.**
개인 메일로 보내는 것도 재배포에 해당한다.

**대신 같은 목적을 합법적으로 달성한다** — 형식·구성은 참고하되,
데이터는 우리가 이미 쓰고 있는 정식 소스에서 직접 모아 **자체 리포트**를 만든다.
형식(목차 구성, 섹션 배열)은 저작권 대상이 아니므로 비슷하게 꾸며도 된다.

## Claude API 활용 (결제 완료됨)

- 뉴스 제목 수십 건 → **핵심 이슈 3~5줄로 요약**
- 테마 등락 데이터 → **"오늘 왜 올랐나" 한 문단**
- 토큰 절약: 원문 전체를 넣지 말고 **제목 + 등락률 숫자만** 전달
- 모델: `claude-sonnet-5` (요약 용도엔 충분). 비용 민감하면 `claude-haiku-4-5-20251001`
- 실패해도 메일은 나가야 함 → 요약 실패 시 원본 데이터만 넣어 발송

## 메일 발송 — 네이버 SMTP


> 텔레그램 봇의 스케줄러·설정 저장 구조를 그대로 재사용한다.
> **텔레그램을 먼저 만들고 뉴스레터를 얹는 순서가 효율적이다.**

# 🌏 미국↔한국 테마 연동 (2026-08-13 요청)

밤사이 미국 시장의 특정 섹터가 움직이면 다음날 국내 연동 테마가 따라가는 패턴을
자동으로 짚어준다. **조간 뉴스레터의 핵심 섹션이 될 기능.**

## 왜 필요한가
사용자 표현 그대로 — "글로벌 흐름에 의한 국내시장도 추격하니깐".
밤사이 NVDA가 급등했으면 아침에 반도체 관련주를 먼저 봐야 하는데,
지금은 미국 지수만 보여줄 뿐 **"그래서 오늘 국내 뭘 보나"가 없다.**

## 구현 방향

### 1. 매핑 테이블 (수동 큐레이션이 현실적)
`server/src/usKrLink.ts` 에 US 티커/섹터 → 키움 테마코드 매핑을 JSON으로.
자동 상관계수 계산도 가능하지만, 초기엔 손으로 넣는 게 정확하고 빠르다.

예시 (실제 테마코드는 ka90001로 조회해서 채울 것):
| 미국 | 국내 연동 테마 |
|---|---|
| NVDA, AMD, TSM, MU | 반도체 대표주, HBM, 반도체 장비/소재 |
| 필라델피아 반도체지수(SOX) | 반도체 전반 |
| TSLA, 리튬/배터리 | 2차전지, 전기차 부품 |
| 코어위브, 슈퍼마이크로, 데이터센터 | 전선/전력설비, AI 인프라 |
| 일라이릴리, 노보노디스크 | 비만치료제, 바이오시밀러 |
| 록히드마틴 등 방산 | 방산, 우주항공 |
| 팔란티어, MSFT AI | AI 소프트웨어, 챗봇 |
| WTI/에너지 | 정유, LPG, 조선(LNG선) |
| 금/은 | 금 관련주 |

### 2. 데이터
- **미국 등락**: Yahoo (`globalMarket.ts` 확장). 개별 티커 추가는 심볼만 넣으면 됨.
  ※ **필라델피아 반도체지수(^SOX)** 를 꼭 추가할 것 — 국내 반도체와 상관성이 가장 높다
- **국내 테마 등락**: 키움 ka90001 (이미 구현됨)
- 둘 다 **기존 자산 재사용**. 새 API 계약 불필요

### 3. 화면 / 알림
- **시황 탭에 "글로벌 → 국내 연동" 카드**: 밤사이 오른 미국 섹터 옆에 대응 국내 테마와
  그 테마의 오늘 등락률을 나란히. "미국 반도체 +2.1% → 국내 반도체 테마 +5.4% (따라감)"
- **조간 뉴스레터 상단 섹션**: 오늘 주목할 테마 3개를 근거와 함께
- 텔레그램 조간 알림에도 한 줄 요약

### 4. 한 단계 더 (선택)
- 실제 **상관계수를 계산해서 매핑을 검증**: 미국 티커 일봉 vs 국내 테마 일별 등락률의
  60일 상관계수. 0.5 미만이면 "연동 약함"으로 표시하거나 매핑에서 제외
- 이렇게 하면 하드코딩 매핑이 낡는 문제를 자동으로 잡아낼 수 있다

## 주의
- **상관관계는 시간이 지나면 변한다.** 매핑을 고정 진리로 표시하지 말 것.
  "과거 이런 경향이 있었다" 수준으로 표현하고, 가능하면 상관계수를 같이 보여준다
- 미국 시장이 쉬는 날(현지 휴장) 처리 필요
- 이건 **참고 지표이지 매매 신호가 아니다.** 화면 문구에 그 톤을 유지할 것

# 📊 API 사용량 추적 확장 (텔레그램/뉴스레터와 함께 반드시)

`server/src/apiUsage.ts`의 provider 목록에 아래를 **반드시 추가**한다.
빠뜨리면 실제로 돈이 나가는 Claude API를 못 보게 된다.

| provider | 한도 | 비고 |
|---|---|---|
| `anthropic` | 없음(종량제) | **호출 수 + 입력/출력 토큰까지 기록.** 다른 API와 달리 비용이 직접 발생 |
| `telegram` | 초당 ~30건 | sendMessage 성공/실패 |
| `mail` | 네이버 일일 발송 제한 있음 | SMTP 발송 성공/실패 |

## anthropic은 특별 취급
- 다른 provider는 "호출 횟수"만 세면 되지만, Claude는 **토큰이 비용**이다
- 응답의 `usage.input_tokens` / `usage.output_tokens`를 같이 누적할 것
- 설정 화면에 **누적 토큰 + 추정 비용(모델별 단가 × 토큰)** 표시
- 하루 예산 상한을 두고, 넘으면 요약을 건너뛰고 원본 데이터로만 리포트 발송하는
  안전장치를 고려 (무한 과금 방지)

## 구현 위치
- `apiUsage.ts` — provider 정의 + 토큰 누적 필드 추가
- `summarize.ts` — Claude 호출 후 `recordApiCall("anthropic", model, "ok", {inputTokens, outputTokens})`
- `SettingsPage.tsx` — 카드 3개 추가, anthropic 카드엔 토큰/비용 표시
