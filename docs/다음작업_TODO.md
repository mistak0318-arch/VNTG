### 미국 국채금리는 종가배팅에 도움이 안 됐다 (2026-08-20 검증)

「금리가 오르는 날은 종가배팅을 하지 않는다」를 조건으로 넣고 과거로 물었다.
삼성전자·SK하이닉스 **243거래일(486건)**, 기준은 **코스피 대비 초과분**.

| 조건 | 남는 건수 | 승률 | 코스피 대비 |
|---|---|---|---|
| 전체(조건 없음) | 486 | 55% | **+0.28%p** |
| 10년물 +6bp 이하 상승 | 458 | 56% | +0.32%p |
| 10년물 **안 오른 날만** | 240 | 59% | +0.29%p |
| 10년물 3bp 이상 **하락** | 98 | 67% | +0.42%p |
| 10년물 8bp 이상 하락 | 10 | 70% | +0.66%p |
| 30년물 +8bp 이하 | 480 | 56% | +0.29%p |
| **선물 양봉** | 264 | 73% | **+0.93%p** |

**읽는 법이 요점이다.** 승률은 53%→70%로 오르는데 **코스피 대비는 거의 안 움직인다.**
금리가 내린 날은 시장 전체가 오른다 — 그날 삼성전자가 오른 건 종목을 골라서가 아니라
지수가 올라서다. 그러면 지수 ETF 를 사면 된다.

「오르면 하지 마라」쪽으로 봐도 같다. 오르는 날을 절반 넘게 걷어내도(486→240건)
초과분은 +0.28 → +0.29%p 로 **사실상 그대로**다.

**지금까지 확실히 일하는 조건은 「미국 선물 양봉」 하나뿐이다**(264건 +0.93%p).

단서: 2종목뿐이고 **생존편향**이 있다(지금 살아있는 종목의 과거만 본다).
−8bp 10건짜리 70% 는 **믿으면 안 되는 숫자**다.
기능은 그대로 두었다 — 게이지는 오늘 금리 상태를 알려 주고, 문턱은 화면에서 바꿔 가며
다시 물어볼 수 있다.

⚠️ **금리는 매수일 *전날* 미국 채권 세션 값을 쓴다.** 미국 채권시장은 08:00 ET(=21:00 한국)에

3. 미국 종목 상세에 **호가·체결·차트**를 붙인다 — 국내 화면 컴포넌트를 그대로 쓴다

5. 미국 시세분석(순위) 화면
6. 실시간 `FE`·`FT` — 되면 한투도 뺄 수 있다

## G. 위젯 · 워치 — **안 열어도 보이게** (2026-08-22 접수, 다음 작업)

> 「이제 틀은 잡혔고, 계속 보면서 시장을 파악하는 게 중요하다.
>  종목 실시간으로 보는 걸 다른 앱으로 하니 좀 일이더라」

**PWA 는 이미 되어 있다(F 항목).** 그러니 남은 건 PWA 로는 **원리적으로 안 되는 것** 둘이다.

### 무엇을 새로 만드나 — 화면을 세 번 만드는 게 아니다

| | 어떻게 | 새로 그리는 것 |
|---|---|---|
| 폰 앱 | 이미 PWA. 주소창까지 없애려면 **TWA** 로 감싸기 | 없음 |
| **바탕화면 위젯** | 네이티브 Kotlin **Glance** | 위젯 한 장(관심종목 5줄 + 지수 3개) |
| **워치 타일** | Wear OS 모듈. **standalone 으로 폰 앱 없이도 된다** | 타일 한 장 |
| 잠금화면 | 안드 14 잠금화면 위젯은 **태블릿만** → 진행 중 **알림**으로 | 알림 한 줄 |

위젯은 웹을 못 쓴다(안드로이드가 직접 그린다). 워치도 브라우저가 없다.
다만 **JSON 하나 읽어 텍스트 몇 줄 찍는 수준**이라 화면 로직을 옮기는 일이 아니다.

### 걸림돌은 기능이 아니라 **인증**

Cloudflare Access 는 브라우저 로그인을 요구하는데 위젯·워치에는 브라우저 세션이 없다.
**서비스 토큰**(Access 에서 발급, 헤더 `CF-Access-Client-Id`/`CF-Access-Client-Secret`)으로
통과한다 — 원래 이런 용도로 있는 기능이다.

⚠️ 시크릿이 기기에 박힌다. 그 토큰용 정책은 **조회 전용 경로만** 열고 **계좌 잔고 경로는 뺀다.**
만료도 짧게 잡는다. (지금 서버가 조회 전용이라 위험이 크진 않지만 계좌는 다르다)

### 만들 화면 — 참고 화면을 받았다 (2026-08-22)

**위젯은 증권플러스, 워치는 네이버 증권 워치앱**을 기준으로 한다.

**위젯 (바탕화면, 세로로 긴 목록)**

```

│ [추세]보유&1등테마(키움)  08.22 00:18  ↻ ⚙ │   제목 = 관심종목 그룹 이름

├──────────────────────────────────────────┤
│ KODEX 200      109,980   1,790 ▲1.65%  32,065,574 │
│ SK하이닉스    1,761,000  70,000 ▲4.14%   8,303,485 │

│ …  스무 줄쯤                                        │

```

- 한 줄 = **종목명 · 현재가 · 대비 · 등락률 · 거래량** (다섯 칸)
- **크기 조절이 된다.** 위 그림은 제일 크게 놨을 때고, 늘 대화면인 게 아니다.
  안드로이드 위젯은 사용자가 손으로 늘렸다 줄인다(`sizeMode`·`onSizeChanged`).
  **줄 수만 줄이는 게 아니라 칸도 줄인다** — 좁아지면 거래량부터 빼고, 더 좁으면
  대비를 빼서 종목명·현재가·등락률 셋만 남긴다. 다섯 칸을 억지로 우겨넣으면 글자가 뭉갠다.

  정해 둔다(2×2 / 4×2 / 4×4 정도).
- 설정(⚙)에서 **어느 그룹을 띄울지** 고른다 — 관심종목 그룹을 그대로 쓴다
- 「통합시세 기준」처럼 **어느 거래소 값인지 적는다**
  (⚠️ 마감 후 통합은 NXT 값이다 — 2026-08-21 에 확인. 위젯에도 같은 함정이 있다)

**워치 (네이버 증권 워치앱 모양)**

```
목록                          상세
┌─────────────────────┐   ┌──────────────────┐
│ AAPL      +0.24%    │   │ ‹  10:09  AAPL   │
│ 225.12  After 224.73│   │ 애플              │
├─────────────────────┤   │ 225.12           │
│ TSLA      -5.77%    │   │ ▲0.89 +0.24%     │
│ 311.218  Pre 326.54 │   │ After 224.73 -0.11%│
└─────────────────────┘   │ [미니 차트]        │
                          └──────────────────┘
```

- 목록 카드 = **티커 · 현재가 · 등락률 배지 · 다른 세션 가격**(After/Pre)
- 다른 세션 표기는 **이미 웹에 있는 `usSession.ts` 규칙 그대로** 쓴다
  (정규장 중엔 안 띄우고, 마감 후엔 애프터, 한국 낮엔 주간거래)
- 상세 = 현재가·대비·등락률·다른 세션 + 미니 차트(분봉)

### 서버에 필요한 것 — 요약 엔드포인트 하나

위젯·워치가 화면 API 를 여러 번 부르면 안 된다. **한 번에 다 담은 작은 JSON** 하나를 만든다.

- 위젯용: `그룹 이름 + 줄마다 {name, price, change, changeRate, volume}` + 기준시각 + 거래소 표기
- 워치용: 위와 같되 해외는 `{afterPrice, afterChangeRate, dayPrice, dayVolume}` 까지
- 공통으로 지수 셋과 신호등 색 정도를 얹어 둔다

### 순서

1. 요약 엔드포인트 + 서비스 토큰 정책
2. 위젯(Glance) — 폰 앱 껍데기 + 위젯 하나
3. 워치 타일
4. (선택) 진행 중 알림으로 잠금화면 대용

## ✅ Z. 종목발굴 — 한 종목을 제대로 보는 자리 (2026-08-19 완료)

「마이페이지 > ⛏️ 종목발굴」로 만들었다. `web/src/pages/StockDiscoveryPage.tsx`.

### 「개별종목분석」과 무엇이 다른가 (판단 완료)

거기는 **탭**이라 한 번에 하나씩 본다. 여기는 **펼쳐 놓고 훑는다.** 둘을 합치지 않았다 —
한 종목을 파고들 때와 백 종목을 넘겨 볼 때는 원하는 게 다르다.
머리에 「개별종목분석으로」 버튼을 둬서 파고들 때 넘어가게 했다.
(후보 절의 「PC/태블릿 넓은 모드」는 이걸로 해결된 것으로 본다)

### 화면의 중심은 종목이 아니라 **넘기기**

- 모집단 셋 — 거래대금 상위 100(시장 필터) · 관심종목 · 신호등 스크리너 최근 결과
- 붙박이 넘기기 바: `◀  12/100 종목명 현재가 등락률  ▶`, 눌러서 목록 펼치기
- **← → 방향키**로 넘긴다. 입력칸에 커서가 있을 때는 가로채지 않는다
- 목록에 없는 종목은 검색해서 **목록 맨 앞에 끼워 넣는다** — 따로 띄우면 넘기기가 죽는다

### 블록 열하나

차트 · 신호등 · 목표주가 · 투자자별 매매동향 · 공매도/대차 · 체결금액대별 ·
재무 · 업종/테마 · 호가 · 거래원 · 메모.
기간 상승률은 블록으로 두지 않았다 — `PriceHeader` 가 이미 들고 있어 두 번 나온다.

배치: 모바일 1열 · 800px 이상 2열 · 1440px 이상 3열. 차트·수급·메모는 전폭.
(`minmax(0,1fr)` 을 쓴다. `1fr` 은 안쪽 표 폭만큼 칸이 벌어져 화면이 옆으로 밀린다)

### 부하를 막은 방법 (설계에 넣으라던 것)

1. **화면에 들어온 블록만 부른다.** 마운트 자체가 API 호출이라 그게 곧 조절기다
2. **「간단히」가 기본** — 차트·신호등·목표주가·수급 넷만 켜고 시작한다
3. 블록별로 끄고 켜며 그 선택을 기억한다(localStorage). 끈 블록은 조회도 안 한다
4. **다음 종목 신호등만** 1.5초 뒤 미리 받는다. 연타로 지나가는 종목은 안 부른다
5. 목록 신호등은 기본 꺼짐 — 백 종목 평가는 무겁다. 켜도 앞의 40개까지

### 겪은 것

- `IntersectionObserver` 도 `requestAnimationFrame` 도 **그리지 않는 탭에서는 콜백이 안 온다.**
  블록이 영영 자리만 차지한 채 남았다. 자리를 직접 재고 타이머로 묶는다
- 증권사 의견 블록이 혼자 1,705px 이 돼 격자가 무너졌다 → 블록마다 높이를 자르고 안에서 구르게

### 아직 없는 것

- **외국인·기관 보유수량 장기 추이** — 키움이 안 준다. 한투에 있는지 확인 필요
- **업종 PER 대비** — 같음. [[vntg-hts-api-constraints]]

## ✅ 신호등 개편 — 한 점수에서 네 축으로 (2026-08-19)

### 왜 바꿨나

코드를 읽고 문제 셋을 찾았다.

1. **전부 O/X였다.** `합계 >= 기준값` 한 줄이라 외국인 순매수 +1백만원과 +5,000억이 같은 1점.
2. **한 숫자로 뭉갰다.** 70점이 「실적 좋고 수급 최악」인지 그 반대인지 알 수 없다.
   살 이유와 팔 이유가 평균에서 상쇄된다.
3. **위험을 깎을 수단이 없었다.** 공매도가 늘든 위에 매물이 잔뜩 걸렸든 감점할 곳이 없어서
   위험한 종목이 초록으로 나올 수 있는 구조였다.

### 무엇을 했나

**추세 · 수급 · 실적·가치 · 위험** 네 축. 종합은 앞의 셋만 가중평균하고
**위험은 섞지 않는다.** 위험이 빨강이면 나머지가 아무리 좋아도 초록을 막는다
(`riskBlocksGreen`, 설정에서 끌 수 있다).

기준값이 하나에서 둘로 — `threshold`(50점)와 `strongAt`(100점). O/X 대신 0·50·100.

새 기준 여섯. **넷은 조회가 안 늘어난다** — 신호등이 이미 받던 일봉·수급 응답에서 나온다:
- `nearHigh` 52주 고점 근접 (추세) · `flowStreak` 외인 연속 순매수 (수급)
- `overhead` 매물 부담 (위험) · `disparity` 이격도 과열 (위험)
- `shortSaleUp` 공매도 · `lendingUp` 대차 — **종목당 +1회씩이라 기본은 꺼 뒀다.**
  설정 화면이 「+1회」 배지와 「100종목이면 100회」를 미리 알려 준다

### 안 깨뜨리려고 한 것 (공통 모듈이다)

`CheckResult.pass` 를 **남겼다.** `watchTracking`·`paperTrade`·`tradeJournal`·`signalScreen`
넷이 이 값을 쓴다. `grade >= 50` 이 통과이고, **위험 기준만 반대로** `grade < 50`(안전)이 통과다.
그래서 위험 기준 이름을 「매물 부담 낮음」처럼 **안전한 상태**로 적었다 —
통과/미달 목록에 그대로 들어가기 때문이다.

`signalConfig.json` 이 이미 저장돼 있어(사용자가 `maLines` 를 `[5,20]` 로 바꿔 둠)
**통째로 덮어쓰지 않는다.** 뼈대는 기본값에서, 사용자가 정한 값(켬/끔·가중치·기준값)만
저장본에서 가져온다. 예전 저장본엔 `axis`·`strongAt` 이 없어 통째로 쓰면 축 없는 기준이 생긴다.

### 실측

- 삼성전자 — 추세 0 · 수급 60 · 실적 100 · 위험 33 → 종합 53(노랑).
  예전 한 숫자로는 표현이 안 되던 그림이다
- 저장 왕복 후 14개 기준 전부 `axis`·`strongAt` 보존, `maLines [5,20]` 유지
- 관심종목 추적·배치 조회 정상 (`pass` 를 쓰는 쪽이 안 깨졌다)

「실패하면 다시 부르고 있나」에서 시작해 결함 셋을 찾았다.

1. **유량 초과일 때만 재시도했다.** 그런데 하루 실패 3,700건에 유량은 0 이었다 —
   **한 건도 재시도되지 않았다는 뜻이다.** 네트워크 끊김·HTTP 5xx·429 도 다시 부르게 했다
   (같은 요청이 다음엔 될 수 있다). 종목 없음 같은 rt_cd 오류는 그대로 던진다
2. **성공 건수가 부풀어 있었다.** `res.ok` 만 보고 「성공」을 기록한 뒤
   `rt_cd !== "0"` 에서 던졌다 — HTTP 200 인 실패가 전부 성공으로 세어졌다
3. **유량을 유량으로 세지 않았다.** 한투는 `rateLimited` 를 한 번도 안 올렸다.
   화면의 「한도초과 0」이 사실이 아니었다

**실패 사유별 집계**를 넣었다(`DayStat.reasons`). 개수만 세면 무엇을 고쳐야 할지 알 수 없다 —
종목이 없어서인지 토큰이 만료돼서인지 유량인지 갈려야 한다.
설정 > 비용·상태에 「실패 사유」로 뜨고, 실패율(%)도 같이 보인다.

**남은 숙제:** 오늘 실패 3,776건(26.6%)의 사유는 아직 「알 수 없음」이다 — 집계를 넣기 전에
쌓인 것이라서다. 하루 돌려 보고 사유가 잡히면 그때 고친다.

## ✅ 시장 흐름 대시보드 — 「맥박」 (2026-08-19)

「시장 흐름 분석」 첫 탭. `server/src/marketPulse.ts` + `web/src/components/MarketPulsePanel.tsx`.

### 다른 화면과 무엇이 다른가

시황 대시보드는 **무엇이 올랐나**를 본다. 여기는 **돈이 어디로 옮겨가고 있나**다.
그래서 전부 며칠을 겹쳐 보고, 하루치 숫자로는 아무 말도 하지 않는다.

### 판정을 서버에서 하는 이유

화면에서 하면 리포트·텔레그램이 같은 판정을 다시 짜야 한다. 같은 시장을 두고 두 곳이
다른 말을 하면 그때부터 무엇도 못 믿는다. **판정은 한 곳에서만** 한다.

### 이 파일이 실제로 만들어 내는 것 셋

나머지는 이미 있는 모듈(신호등·시장폭·선물·금리·미장·글로벌)을 모으는 것이고,
새로 계산하는 건 이 셋이다.

1. **자금 국면** — 외인·기관·개인 5일 누적의 조합 →
   동반유입 / 외국인주도 / 기관주도 / 개인홀로 / 동반이탈 / 혼조
2. **방향 전환** — 이게 제일 쓸모 있다. 실측에서 외국인 5일 누적이 **+4.7조**인데
   최근 **2일 연속 순매도**였다. 5일 합만 보면 「외국인 주도」로 보이지만 지금 손은
   반대로 가고 있다. **누적과 최근 방향이 어긋나면 그게 변곡점**이라 따로 낸다
3. **지수·폭 다이버전스** — 지수는 오르는데 오르는 종목 수는 줄고 있는가.
   꼭지에서 늘 먼저 나오는데 지수만 보면 멀쩡해 보인다

### AI 판독 (맨 위)

**숫자를 다시 읽어 주는 요약은 쓸모가 없다.** 「외국인 5일 +4.7조」는 이미 화면에 있다.
프롬프트가 셋을 강제한다 — 숫자 나열 금지 / **틀릴 조건을 지표와 값으로** 반드시 적을 것 /
모르면 모른다고 할 것. 「틀릴 조건」이 있어야 나중에 복기가 된다.

- 숫자와 **따로** 연다(`/api/pulse` · `/api/pulse/brief`). 한 요청에 묶으면 화면을 열 때마다 돈이 나간다
- 서버가 10분 캐시 + **국면·위험이 그대로면 아예 다시 안 부른다**
- 입력이 작다 — 실측 **입력 770 · 출력 274 토큰**. 리포트(8,300)의 십분의 일이다
- 모델은 설정 > 분석 기준 > AI 모델의 「시장 흐름 요약」에서 고른다.
  **안 고르면 데일리 리포트에 고른 모델을 따라간다** (아래 참조)

## ✅ 차트 크게 보기 (2026-08-19)

폰에서 320px 차트로는 밑꼬리도 이평선 교차도 안 보인다. 도구줄에 **⤢ 크게**를 붙였다.

**셋을 겹쳐 쓴다** — 하나만 믿으면 안 되는 자리다.
1. **오버레이**(`position:fixed; inset:0`) — 이게 본체다. 어디서든 된다
2. **Fullscreen API** — 되면 얹는다. 주소창·탭까지 없애 준다.
   ⚠️ **iOS 사파리는 video 가 아닌 요소에 안 준다**
3. **`orientation.lock("landscape")`** — 안드로이드 크롬에서만 된다. iOS 는 무시한다

셋 다 실패해도 오버레이는 남으므로 어디서든 크게는 보인다. ESC·닫기·`fullscreenchange`
어느 쪽으로 나가도 상태가 맞는다(안 맞추면 전체화면만 풀리고 오버레이가 남아 화면이 잠긴다).

- `CandleChart` 에 `height` 를 받게 했다. 높이가 바뀌어도 **차트를 다시 만들지 않는다** —
  다시 만들면 확대해 둔 구간이 풀려서 전체화면이 오히려 방해가 된다. `applyOptions` 만 쓴다
- 전체화면에서는 판독 줄을 **접어 둔다**(「판독」 버튼으로 켠다). 크게 보려고 들어온 자리다
- **눕힌 폰(높이 500px 미만)에서는 머리줄도 접는다.** 375px 짜리 화면에서 머리줄·도구줄이
  108px 를 먹으면 차트가 59% 밖에 안 된다 → 62px 로 줄여 **83%** 로 만들었다

## ✅ 관심종목 그룹 바 (2026-08-19)

그룹이 늘면 **만든 순서대로** 늘어서 자주 보는 게 뒤로 밀렸고, 옮길 방법이 없었다.

- **◀ ▶ 로 순서를 옮긴다.** 끌어 옮기기(drag)를 안 쓴 이유 — **폰에서 안 된다.**
  이 앱은 폰으로 보는 시간이 더 길고 터치 드래그는 스크롤과 싸운다. 두 칸이면 어디서든 되고
  한 칸씩 정확히 움직인다
- **평소에는 안 보인다.** 「정리」를 켰을 때만 화살표와 ✎ 가 붙는다 —
  늘 붙어 있으면 고르려다 잘못 눌러 순서가 바뀐다
- 그룹 이름을 눌러 **이름 변경**(정리 모드에서만). 개수는 이름보다 흐리게 —
  이름이 먼저 읽혀야 한다

서버 `reorderGroups` 는 **화면이 보낸 순서를 그대로 믿지 않는다.**
화면이 모르는 그룹(다른 창에서 방금 만든 것)이 있을 수 있어 **보내온 것 먼저, 빠진 것은 뒤에**
붙인다. 실측으로 확인했다 — 그룹 하나만 보냈는데 나머지 둘이 그대로 남았다.
기본 그룹은 늘 맨 앞이고 옮길 수 없다.

라우트 순서 주의: `PUT /groups/reorder` 를 `PATCH /groups/:name` **보다 먼저** 등록해야 한다.
안 그러면 `:name` 이 "reorder" 를 그룹 이름으로 먹는다.

  **「집계 초과」**로 밝힌다 — 키움이 32비트를 넘기면 잘라 준다.
- **복기를 한 줄로** — 즉시 발행 제외, 채점 가능한 최근 것을 기본 선택, 드롭다운,

- **테마 체크포인트를 「내 테마」에서만** — AI 가 아무 이름이나 찍으면 채점이 안 된다.

### 6. 외부 접속 (HTTPS + 인증) — **설계부터**

> "회사에서도 보고 싶은데 미니PC가 토큰을 다 들고 있고 통신도 HTTP라 위험하다.
> 미러링하는 별도 웹서버를 HTTPS로 띄우고 ID/PW + OTP + 이메일(또는 텔레그램) 인증"

**결론부터: 가능하다. 다만 「미러링」보다 「앞단에 인증 게이트웨이」가 맞다.**

- 지금 서버는 **조회 전용**이라 유출 위험의 본체는 시세가 아니라 **API 키·텔레그램 세션**이다.
  그건 `.env` 와 `server/data` 에 있고 **HTTP 응답으로는 안 나간다.** 별도 서버로 데이터를
  복사하면 오히려 **비밀이 두 곳에 생긴다** — 미러링이 더 위험하다.
- 맞는 구조: 미니PC 안에서 **리버스 프록시(Caddy 등)** 를 앞에 세워
  ① HTTPS 종단 ② 인증 통과한 요청만 기존 서버로 넘김.
  데이터를 복사하지 않으므로 실시간이고, 비밀은 그대로 한 곳에 있다.
- 인증은 **텔레그램 봇이 가장 싸다.** 이미 봇이 붙어 있어 메일 SMTP 를 새로 안 붙여도 되고,
  로그인 시 봇이 코드를 보내면 그게 곧 2단계다. ID/PW + 텔레그램 코드면 충분하다.
- ⚠️ **집 IP 를 인터넷에 여는 일**이다. 포트포워딩 대신 **Cloudflare Tunnel** 을 쓰면
  공인 IP 노출 없이 HTTPS 가 붙는다. 이쪽을 먼저 검토할 것.
- ⚠️ 이건 **보안 경계를 만드는 작업**이라 대충 하면 안 된다. 세션 쿠키·CSRF·무차별 대입
  차단까지 같이 봐야 한다. **다른 기능과 섞지 말고 따로 한 세션을 잡을 것.**
