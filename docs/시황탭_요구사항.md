## A-2. 국내 지수 + 투자자 수급 (2×2 카드)

**4개 카드**: KOSPI / KOSDAQ / 코스피200 / 선물(코스피200 선물)

각 카드에 표시할 내용:
- 지수 현재가
- 전일대비 (▲▼ 포함) + 등락률
- **미니 차트** — 전일 종가 대비 당일 흐름 (분봉 기반 스파크라인)
- 하단에 **외국인 / 기관 / 개인 순매수 (억원)**
- 장 상태 표시 (장전 / 장중 / 장마감)

> **검토 포인트**: 미니 차트까지 넣으면 분봉 데이터를 추가로 받아야 해서 호출량이 늘어납니다.
> 1차 구현에서 빼고 나중에 붙일지, 처음부터 넣을지 결정 필요.

## B. 공통 UI 요구사항

- **색상 규칙**: 상승/순매수 = 빨강, 하락/순매도 = 파랑, 보합 = 검정 (한국식)
- **반응형**: 폰 / 태블릿 대응. 폰에서는 1열, 태블릿에서는 2열 배치
- **자동 갱신**: 섹션별 갱신 주기 분리 (아래 C-2)
- **갱신 시각 표시**: 각 섹션에 마지막 업데이트 시각
- **장 상태 배지**: 장전 / 장중 / 장마감 / 휴장
- **스켈레톤 로딩**: 데이터 로딩 중 레이아웃 흔들림 방지
- **에러 처리**: 특정 섹션 실패 시 그 섹션만 에러 표시, 나머지는 정상 표시

## C. 기술 검토 사항 (Claude Code에 확인시킬 것)

### C-1. 데이터 소스 매핑 (확정)

**원칙: 공식 API 우선. 크롤링은 대체 수단이 없는 경우에만.**

| 항목 | 소스 | 상태 |
|------|------|------|
| 달러/원 | 한국은행 ECOS API 또는 Yahoo `KRW=X` | API |
| WTI유 | Yahoo Finance `CL=F` | API |
| US 30 / 500 / Tech 100 / 2000 | Yahoo Finance (지수선물 심볼) | API |
| S&P 500 VIX | Yahoo Finance `^VIX` | API |
| 미국 10년/30년 국채금리 | **FRED API** (`DGS10` / `DGS30`, 미 연준 공식·무료) | API |
| 비트코인 | 업비트 또는 바이낸스 퍼블릭 API | API |
| 증시주변자금 | 키움 → 없으면 금융투자협회 freeSIS | API |
| 업종별 등락률 | 키움 → 없으면 KRX 정보데이터시스템 | API |
| VI 발동 종목 | 키움 (실시간/WebSocket 여부 확인) → KRX | 확인 필요 |
| **테마별 등락률** | **키움 섹터/테마 분류 우선 확인** ← 저녁에 시도 | **확인 필요** |

#### 테마 분류 — 확인 순서

**1순위 (먼저 시도)**: 키움 자체 제공 활용
- 키움에 종목 섹터/테마 분류 맵이 제공되므로 이걸로 해결 가능성 있음
- 확인할 것: 분류 조회 TR 존재 여부, 분류 체계의 세분화 수준(업종 수준인지 테마 수준인지),
  MTS 화면의 테마 목록과 일치하는지

**2순위 (대안 — 1순위 실패 시에만)**: 외부 크롤링
- 네이버 금융 등에서 **테마 → 구성 종목 매핑만** 크롤링
- 시세는 키움 API로 조회, 크롤링은 매핑 테이블 용도로만 사용
- 하루 1회 배치로 `theme_map.json` 갱신
- 크롤링 실패 시 이전 매핑 파일 유지 (fallback) → 시세는 계속 정상 동작
- 등락률 계산은 테마 내 종목 **단순평균** (시총가중은 대형주 편중으로 체감과 괴리)
- robots.txt 확인, 요청 간격 1초 이상, User-Agent 명시

> **미결정**: 테마를 전체(200개 이상) 가져올지, 관심 테마만 추릴지.
> 상위/하위 5개만 볼 거라면 전체 종목 시세 조회는 호출량 대비 비효율일 수 있음.

### C-2. 갱신 주기 설계 (제안)

| 섹션 | 제안 주기 | 근거 |
|------|-----------|------|
| A-1 글로벌 | 30초 ~ 1분 | 외부 API 호출 제한 고려 |
| A-2 지수 | 5 ~ 10초 | 가장 자주 봄 |
| A-3 수급 | 30초 ~ 1분 | 원 데이터가 자주 안 바뀜 |
| A-4 주변자금 | 1일 1회 | D+2 지연 데이터 |
| A-5 등락현황 | 30초 | |
| A-6~A-9 | 1 ~ 5분 | 순위는 급변하지 않음 |

### C-3. 캐싱 아키텍처 (필수)

```
[스케줄러] → 키움/외부 API 폴링 → [서버 메모리 캐시] → [REST 엔드포인트]
                                                              ↑
                                                    [브라우저] 폴링 또는 SSE
```

- 클라이언트가 키움 API를 **직접 호출하지 않을 것** (앱키 노출 방지 + rate limit)
- 브라우저 여러 개(폰/태블릿/PC) 동시 접속해도 키움 호출량은 동일하게 유지
- 장 마감 후에는 폴링 중단하여 불필요한 호출 방지

### C-4. API 제공 여부 확인 필요 목록

- [ ] 시장 전체 투자자별 순매수 집계 TR
- [ ] 기관 세부 구분 (금융투자/투신/연기금/사모) 필드 제공 여부
- [ ] 선물 투자자별 매매동향 TR (파생 카테고리)
- [ ] 증시주변자금 (고객예탁금/미수금/신용잔고/선물예수금) TR
- [ ] 종목등락현황 집계 TR
- [ ] 업종별 등락률 TR
- [ ] **테마/섹터 분류 조회 TR** ← 키움 종목 섹터맵으로 해결 가능한지 저녁에 확인. 안 되면 크롤링(C-1 2순위)
- [ ] 250일 신고가/신저가 TR
- [ ] **VI 발동 종목 TR** ← 실시간 이벤트일 가능성. WebSocket 여부 확인
- [ ] 지수 분봉 (미니 차트용)
