# 텔레그램 알림 봇 — 구현 설계서

작성: 2026-08-12 · **다음 세션에서 이 문서대로 구현하면 됨**

---

## 0. 시작 전에 사용자가 미리 해둘 것 (Claude 한도 불필요)

### ① 봇 생성
1. 텔레그램에서 **@BotFather** 검색 → 대화 시작
2. `/newbot` 입력
3. 봇 이름 입력 (예: `VNTG HTS 알림`)
4. 봇 아이디 입력 — `_bot`으로 끝나야 함 (예: `vntg_hts_alert_bot`)
5. **토큰**을 받음 (`8123456789:AAH...` 형태) → 메모해둘 것

### ② 내 chat_id 알아내기
1. 방금 만든 봇을 검색해서 대화 시작 → **아무 메시지나 전송** (필수. 안 보내면 봇이 나에게 못 보냄)
2. 브라우저에서 아래 주소 열기 (`<토큰>` 부분 교체):
   ```
   https://api.telegram.org/bot<토큰>/getUpdates
   ```
3. 응답에서 `"chat":{"id":123456789` 의 숫자가 **chat_id**

### ③ .env에 추가 (메인 PC와 미니PC 양쪽)
```
TELEGRAM_BOT_TOKEN=8123456789:AAH...
TELEGRAM_CHAT_ID=123456789
```

## 1. 무엇을 알릴 것인가 (확정 필요 — 다음 세션 첫 질문)

후보:
- **A. 알고리즘 스캔 결과** — 기존 `algoScan.ts`가 뽑은 종목을 장중 특정 시각에 푸시
- **B. 관심종목 급등락** — AI_HTS 관심종목이 ±N% 움직이면 즉시
- **C. 관심종목 수급 이상** — 외국인/기관 순매수가 평소 대비 급증
- **D. 장 마감 요약** — 지수·내 관심종목 등락·수급 한 장 요약

> 권장 시작점: **D(마감 요약) + B(급등락)**.
> D는 하루 1회라 안전하고, B는 실시간성이 있어 체감이 큼.
> A는 스캔이 무거워서(종목당 여러 TR) 장중 반복 실행에 부담.

## 2. 서버 구조

### 새 파일: `server/src/telegram.ts`
```ts
export async function sendTelegram(text: string): Promise<void>
```
- `https://api.telegram.org/bot<TOKEN>/sendMessage`
- body: `{ chat_id, text, parse_mode: "HTML", disable_web_page_preview: true }`
- 토큰 없으면 **조용히 skip** (개발 PC에서 안 터지게)
- `recordApiCall("telegram", "sendMessage", ...)` 로 사용량 집계 (기존 `apiUsage.ts` 재사용)
- 텔레그램 제한: 메시지 4096자, 초당 ~30건 → 길면 잘라서 여러 건

### 새 파일: `server/src/alertScheduler.ts`
- `setInterval` 기반. **cron 라이브러리 추가하지 말 것** (의존성 최소화)
- 한국시간 기준 판단 함수 필요 (서버는 이미 KST 환경이지만 명시적으로)
- 장 운영일 판단: 주말 제외 + 공휴일은 **키움 응답이 비면 휴장으로 간주** (공휴일 API 없음)

동작:
| 시각 | 동작 |
|---|---|
| 09:00~15:30, 5분마다 | 관심종목 시세 확인 → 임계치 넘으면 알림 (종목당 하루 1회만) |
| 15:40 | 마감 요약 1건 |

### 라우트: `server/src/routes/alerts.ts`
- `GET /api/alerts/config` — 현재 설정
- `POST /api/alerts/config` — 임계치·on/off 저장 (`server/data/alertConfig.json`)
- `POST /api/alerts/test` — **테스트 발송** (설정 화면에서 버튼으로)

### 설정 화면
`web/src/pages/SettingsPage.tsx`에 섹션 추가:
- 봇 연결 상태 (토큰 설정됨/안됨 — 값은 절대 노출 금지)
- 급등락 임계치 (기본 ±5%)
- 마감 요약 on/off
- **테스트 발송 버튼**

## 3. 중복 알림 방지 (중요)

5분마다 도는데 같은 종목이 계속 조건을 만족하면 알림이 폭주함.

```
server/data/alertState.json
{ "20260812": { "005930": ["surge"], "000660": ["surge","plunge"] } }
```
- 날짜별 + 종목별 + 알림종류별로 **하루 1회**만 발송
- 날짜 바뀌면 자동 초기화

## 5. 주의사항

- **주문 기능은 절대 넣지 말 것.** 이 앱은 조회 전용. 봇으로 매매 명령을 받는 구조는 만들지 않는다
- 봇 토큰은 `.env`에만. 설정 화면·로그·git 어디에도 값이 나오면 안 됨
- 텔레그램 발송 실패가 서버를 죽이면 안 됨 → 전부 try/catch, 실패는 로그만
- 키움 API 부하: 관심종목 20개면 5분마다 20콜. TR당 초당 5회 제한이라 **순차 호출 + 약간의 딜레이** 필요 (`algoScan.ts`의 기존 패턴 참고)
- 미니PC는 24시간 켜져 있으므로 스케줄러가 계속 돎 → 메모리 누수 없게 setInterval 하나만

## 6. 구현 순서 (다음 세션)

1. 알림 종류 확정 (위 1번)
2. `telegram.ts` + `POST /api/alerts/test` → **테스트 발송부터 성공시키기**
3. 설정 화면에 연결 상태 + 테스트 버튼
4. 마감 요약 (하루 1회라 검증 쉬움)
5. 급등락 알림 + 중복 방지
6. 미니PC 배포 (`git push` → `update.cmd`)

> 2번까지만 돼도 "봇이 살아있다"가 확인되므로, 거기서 한 번 끊고 가도 됨.
