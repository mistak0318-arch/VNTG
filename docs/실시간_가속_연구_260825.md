# 실시간 갱신 가속 연구 (2026-08-25)

「KRX·NXT·미장 실시간을 더 빠르게 — 특히 시세분석·관심종목처럼 목록이 큰 화면에서」
에 대한 조사. 현재 구조 실측 → 병목 → 개선안(효과 순).

## 지금 값은 몇 살인가 — 화면별 실측

| 화면 | 갱신 경로 | 값의 나이 |
|---|---|---|
| 종목 상세(현재가) | ka10001 REST 폴링 | 1초 |
| 호가/프로그램 | 실시간 store → `/latest` 폴링 | 1~3초 |
| 해외 관심종목 | 한투 REST 5초 + FE 오버레이 2.5초 | 2.5~5초 |
| **시세분석(순위)** | rank TR 자동 20초 | **최대 20초** |
| **관심종목(VNTG)** | watchlistTracking 40초 | **최대 40초** |

키움 웹소켓 틱은 서버 store 에 **즉시** 쌓인다. 즉 병목은 키움이 아니라
**서버→브라우저 구간과, 목록 화면이 실시간을 아예 안 쓰는 것**이다.

## 제약 (실측·문서 확인된 것)

- **한 연결에 200종목** (105115·105118·105110 실측). 190 스케줄러 + 10 화면 몫.
  낮 국면: 관심종목 + 코스피95·코스닥95 거래대금 상위.
- `/api/realtime/latest` 는 **키 40개 상한** + 부를 때마다 임시구독을 태운다 —
  100줄짜리 표에는 지금 구조로 못 붙인다.
- NXT 는 통합 0B 에 이미 섞여 온다(FID 9081 이 KRX/NXT 구분) — 별도 채널 불요.
- 미장 FE: 등록 통과, **프레임 실측은 오늘 밤** (미확정이면 미장 실시간은 아직 없다).
- 우회 사례 조사: [키움 REST 가이드](https://algolab.co.kr/blog/kiwoom-rest-api-algotrading-guide-2026) ·
  [제한 우회 글](https://myip.co.kr/board/read.php?id=2466&table=tip)은 **타 증권사(LS)로
  갈아타는 방법**이라 우리에겐 해당 없음. 같은 앱키로 웹소켓 두 개가 되는지는
  **문서에 없다 — 실측만이 답** (아래 3번).

## 개선안 (효과 순)

| # | 무엇 | 효과 | 크기 |
|---|---|---|---|
| 1 | **목록 화면 실시간 오버레이** — 시세분석·관심종목 줄의 현재가·등락률을 store 값으로 덧씌운다 (해외 관심종목이 이미 하는 방식). 시세분석 상위 190 과 관심종목 전부가 **이미 KEEP 구독** 중이라 키움 호출 0 증가. 서버는 `/latest` 에 **읽기 전용 모드**(`sub=0`, 구독 안 함·키 상한 120)를 추가 | 20~40초 → **1.5초** | 중 |
| 2 | **SSE 푸시** — `/api/realtime/stream` 으로 프레임 도착 즉시 밀어준다(키당 250ms 스로틀). 폴링 HTTP 왕복이 사라지고 틱→화면 0.5초 미만 | 1.5초 → **0.3초** | 중 |
| 3 | **연결 2개 실측** — 같은 토큰으로 웹소켓을 하나 더 열어 REG 200 이 따로 잡히는지, 기존 소켓이 쫓겨나는지 장중에 잰다. 되면 정원 190→380 (시세분석 300~500위까지 커버, NXT 단독 급등주 그룹 추가) | 커버리지 2배 | 소(탐침)+중(적용) |
| 4 | 시세분석 자동갱신 20초→10초 (순위 재편 자체는 TR 로만 가능 — ka10032 연속 3콜/10초는 한도의 6%) | 순위 재편 2배 빠름 | 소 |
| 5 | 미장: FE 프레임 실측 확정 후 FE 를 주 소스로(밤 150 구독), 한투 5초 폴링은 FE 미커버 종목만 | 미장 5초 → 2.5초 이하 | FE 실측에 달림 |

추천 순서: **1 → 4 → 2 → 3(탐침) → 5**. 1이 끝나면 2는 같은 배관에 밀어넣기만
바꾸는 것이라 이어서 하기 좋다.
