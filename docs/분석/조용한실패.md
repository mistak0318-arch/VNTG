# 조용한 실패 — ③회차

2026-09-04. [지도](지도.md) · [중복계산](중복계산.md) 다음.

> 찾는 것: **잘못됐는데 아무도 모르는 자리.** 성적이 안 나오는 것보다
> **성적이 없다는 것을 모르는** 상태가 비싸다. 종가배팅이 두 달 안 돈 이유가 그것이었다.

## 세어 본 것

| | 곳 |

| 아무것도 안 하는 `catch` | 244 |
| `.catch(() => undefined)` 류 | 487 |
| 기록하거나 알리는 `catch` | 26 |

730 대 26. 그런데 **대부분은 정당하다.** `localStorage` 읽기, 곁들이 정보 채우기,
텔레그램 발송처럼 실패해도 본 일이 계속돼야 하는 자리들이다. 숫자 자체는 병이 아니다.

**병은 세 가지 모양으로만 나타난다:**

1. **모르면 하는 쪽으로 기운다** — 못 읽었는데 「괜찮다」로 읽어 사 버린다
2. **「안 했다」와 「못 했다」가 화면에서 같다** — 사람이 구분할 방법이 없다
3. **설정이 없어 통째로 꺼져 있는데 아무 데도 안 적힌다**

아래는 세 모양으로 걸러 낸 것만이다.

## ★ 고쳤다 — ① 모르면 하는 쪽

### A. 연금의 시장 문이 「못 읽으면 산다」였다

`server/src/cisPensionRun.ts`

```ts
const gate = await marketGate(client, cfg.rules).catch(() => null);
const canOpen = gate?.ok !== false;   // null → true → 산다
```

`marketGate` 는 제 안에 이렇게 적어 두고 있다:

> 못 읽었으면 **안 사는 쪽**이다. 모르는 시장에서 사는 것이 가장 비싸다.

그런데 **부르는 쪽이 그 원칙을 뒤집고 있었다.** `!== false` 는 `null`(모른다)을 통과시킨다.
「모른다」는 「괜찮다」가 아니다.

→ `gate?.ok === true` 로 고쳤다. 일지에도 「시장 판단을 못 읽어 새로 담지 않았다
(정리·리밸런싱은 했다)」로 적힌다.

**이건 같은 날 내가 만든 것이다.** 연금에 시장 문을 새로 달면서 기본값을 잘못 잡았다.

### B. 장세 신뢰도는 「끈 것」과 「못 잰 것」이 같은 값이었다

`server/src/cisTrader.ts` `marketGate`

```ts
rules.useRegimeGate === false ? Promise.resolve(null) : regimeTrust().catch(() => null)
const regimeOk = !reg?.weak;   // 둘 다 null → 둘 다 통과
```

껐으면 통과가 맞다. 그런데 **못 쟀을 때도 같은 값**이라 일지에는 그냥 「매수 허용」이라고만
남았다. 나중에 그날을 다시 볼 때 **장세를 보고 통과한 것인지 못 보고 통과한 것인지 알 수 없다.**
이 장부의 값어치는 판단과 근거를 한 줄에 묶는 데 있는데 그 줄이 비어 있었다.

→ **통과 여부는 안 바꿨다.** 장세 자료는 마감 뒤 파이프라인이 만드는 것이라 장중엔 없을 수
있고, 없다고 매수를 통째로 멈추면 그게 더 큰 고장이다. 바꾼 것은 **적히느냐**다 —
일지에 「⚠️ 장세 신뢰도를 못 읽어 그 문은 안 걸렸다」가 붙는다.

## 확인했으나 손대지 않음 — 이미 생각해 둔 자리들

### 잡주 거르개는 「모르면 안 거른다」인데, 그게 맞다

`signalScreen.ts` 는 거래대금이 0(모른다)이면 **빼지 않는다.** 코드에 이유가 적혀 있다:

> 주체별 순매수 목록처럼 원장에서 세운 모집단은 스냅샷을 못 메우면 0 이 남는데,
> 그걸로 빼면 **그 목록이 통째로 사라진다.** 판정 단계에서 다시 걸린다.

「모르면 통과」인데 **뒤에 문이 하나 더 있다.** 한 문만 있을 때와 다른 이야기다.
이런 게 제대로 생각해 둔 모양이다.

### 항해일지 스케줄러 실패는 화면에 뜬다

`cisSchedulerState()` → `/api/cis/watch` 의 `failures` → `CisPage` 가 그린다.
세 번 실패해 포기한 것도 목록에 남는다. **이건 이미 뚫려 있다.**

⚠️ 종가배팅이 두 달 조용했던 이유는 이것과 **다른 길**이었다 — 실패로 세지 않고
`continue` 했기 때문에 `tried` 에 아예 안 들어갔다. 같은 날 마감선을 넣어 고쳤다.
**기록 장치가 있어도 그 앞에서 새면 소용이 없다**는 사례로 남긴다.

## 남은 위험 — 아직 안 고침

### ① 설정이 없으면 통째로 꺼지는 것들

| 관문 | 꺼지는 것 | 파일 수 |
|---|---|---:|
| `isReaderConfigured` | 채널 수집 · 버즈 레이더 · 키워드 알림 | 4모듈 |
| `isMailConfigured` | 로그인 메일 · **주문 기기 등록** | 2모듈 |
| `isTradeConfigured` | 거래 통계 | 2모듈 |
| `isTelegramConfigured` | 슈퍼신호등 알림 | 1모듈 |
| `isAskConfigured` | 시스 질문 | 1모듈 |
| `isWebResearchConfigured` | 웹 조사 | 1모듈 |

각각은 **정당한 방어**다(키 없이 부르면 터진다). 문제는 **꺼져 있다는 사실이 한 곳에
모여 있지 않다**는 것이다. 「왜 버즈가 안 와?」를 물었을 때 답이 여섯 파일에 흩어져 있다.

→ **제안:** 설정 화면에 「지금 꺼져 있는 기능」 한 판. 관문 여섯을 한 줄씩 적고 왜 꺼졌는지
(어느 환경변수가 비었는지) 말한다. 오늘 텔레그램 주문 방이 「전용 방 없음 → 기본 방」으로
새고 있던 것도 같은 종류였고, 표에 줄을 넣자마자 보였다.

### ② 장중 감시가 값을 하나도 못 읽으면 하루 종일 조용하다

`cisWatch.ts`

```ts
if (px.size === 0) return; // 하나도 못 읽었으면 아무 판단도 하지 않는다
```

판단을 멈추는 것은 **맞다.** 다만 이 상태가 이어져도 아무 데도 안 남는다 —
손절선이 걸린 종목을 들고 있는데 감시가 죽어 있으면 그건 알아야 하는 일이다.

→ **제안:** 연속 N회(예: 10분) 값을 못 읽으면 한 번만 알린다. 「감시가 눈을 감고 있다」는
주문 실패만큼 중요하다.

### ③ 스케줄러 25개가 서로를 모른다

[지도](지도.md) 4절에서 적은 것. `afterClose` 만 「시각이 아니라 차례」로 고쳤고
나머지 24개는 시각으로 돈다. 앞 작업이 안 끝나도 다음이 돈다.

오늘 종가배팅이 그 피해자였다 — 마감 뒤 파이프라인이 늦으면 원장이 없고, 원장이 없으면
종배가 조용히 건너뛰었다. **한 번 난 사고는 다른 스케줄러에서도 날 수 있다.**

→ ⑥회차에서 25개의 시각과 의존을 표로 만든다.
