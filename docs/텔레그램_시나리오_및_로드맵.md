# 1. 텔레그램 활용 시나리오

## 1-0. 전제 — 채널 180개를 보고 있다는 게 핵심 문제다

지금 사용자는 텔레그램 채널을 **180개** 구독 중이다. 여기에 우리 봇이 하나 더 끼면
**그냥 묻힌다.** 그러므로 설계 원칙은 하나다:

> **알림 개수를 늘리지 말고, "내가 반드시 봐야 할 것"만 골라 보낸다.**

하루 20건이 오는 봇은 3일이면 음소거된다. 하루 3~5건이 오되 그게 다 쓸모 있으면 살아남는다.

## 1-1. 채널 구조 — 하나로 다 보내지 말 것

텔레그램은 봇 하나로 여러 대화방에 보낼 수 있다. **성격이 다른 알림을 섞지 않는다.**

| 대화방 | 성격 | 빈도 | 알림음 |
|---|---|---|---|
| **VNTG 리포트** | 조간/장중/석간 정기 리포트 | 하루 3건 | 켬 |
| **VNTG 시그널** | 관심종목 급변·조건 충족 | 하루 0~5건 | 켬 |
| **VNTG 로그** | 발행 실패, API 한도, IP 변경 등 시스템 | 드묾 | **끔** |

구현: `.env`에 `TELEGRAM_CHAT_ID_REPORT` / `_SIGNAL` / `_LOG`.
미설정이면 전부 기본 `TELEGRAM_CHAT_ID`로 폴백.

## 1-2. 시나리오 A — 정기 리포트 (구현 완료, 개선 여지)

이미 07/12/18시 발행 + 전송이 동작한다. 개선할 점:

- **텔레그램은 요약만, 상세는 링크로.** 지금은 AI 요약 전문을 보낸다.
  → 핵심 3줄 + "전체 보기" 버튼(웹 링크)이 모바일에서 훨씬 낫다
- **인라인 버튼** 추가: `[전체 리포트] [관심종목] [테마맵]` → Tailscale 주소로 딥링크
  (`reply_markup.inline_keyboard`. 웹훅 없이 URL 버튼만 쓰면 서버 부담 0)

## 1-3. 시나리오 B — 관심종목 시그널 (미구현, 가치 최상)

**이게 진짜 텔레그램을 쓰는 이유다.** 리포트는 웹에서 봐도 되지만, 이건 즉시성이 생명이다.

발동 조건 (전부 이미 있는 데이터로 판단 가능):

| 시그널 | 조건 | 왜 중요한가 |
|---|---|---|
| **급변** | 관심종목 ±5% (설정 가능) | 놓치면 안 되는 움직임 |
| **수급 전환** | 외국인/기관 5일 순매수가 매도→매수로 전환 | 추세 변곡점 |
| **거래량 급증** | 당일 거래량이 20일 평균의 3배 이상 | 뭔가 일어났다는 신호 |
| **신고가** | 250일 신고가 진입 | 저항 돌파 |
| **정배열 진입** | 5>20>60>120 정렬 달성 | 기술적 전환 |
| **공시** | DART 신규 공시 (유상증자·자사주·수주 등 중요 유형만) | 즉시 반응 필요 |
| **뉴스** | 관심종목이 **3개 매체 이상**에 동시 등장 | 시장이 주목 시작 |

**중복 방지가 핵심**: 같은 종목·같은 시그널은 하루 1회. `server/data/alertState.json`.

**메시지 형식** (한 건에 다 담아 스크롤 최소화):
```
🔴 SK하이닉스 +6.2%  1,504,000
거래량 4.2M (20일 평균 2.1배)
외인 5일 +8,521억 · 기관 +2,889억
업종 전기/전자 +5.9% (코스피 1위)
"[특징주] 삼성전자·SK하이닉스 동반 급등" 외 11개 매체
```

## 1-4. 시나리오 C — 장 시작 전 브리핑 (08:30)

조간(07:00)과 별개로, **개장 20분 전**에 짧게.
- 밤사이 미국 마감 + 오늘 주목 테마 3개
- 내 관심종목 중 **간밤 뉴스가 있었던 것만**
- 오늘 일정 (캘린더 연동)

3~4줄이면 충분. 출근길에 보는 용도.

## 1-5. 시나리오 D — 조회 명령 (양방향, 선택)

봇에게 종목명을 보내면 현재가·수급·차트를 돌려주는 방식.
- 구현: `getUpdates` 롱폴링 (웹훅은 공인 IP·HTTPS 필요해서 부적합)
- **주의: 절대 주문 기능은 넣지 않는다.** 조회만.
- 우선순위는 낮다. 웹앱이 이미 있으니 급하지 않음

## 1-6. 구현 순서

1. `alertScheduler.ts` — 장중 5분 간격 시그널 검사 (시나리오 B)
2. 중복 방지 상태 저장
3. 설정 화면에서 임계치·on/off
4. 대화방 분리 (`_REPORT` / `_SIGNAL` / `_LOG`)
5. 리포트 메시지에 인라인 버튼
6. (선택) 08:30 개장 전 브리핑
7. (선택) 양방향 조회

# 2. 시장 흐름을 더 잘 읽기 위한 시나리오

지금까지 만든 데이터로 **아직 안 쓰고 있는 조합**들이다.

## 2-1. 자금의 "이동"을 보여주기 (지금은 스냅샷만 있음)

현재는 "오늘 외국인 +2.3조"만 안다. 정작 중요한 건 **어디서 빼서 어디로 넣었나**다.

- **업종별 외국인·기관 순매수 순위** — 어제 vs 오늘 비교하면 자금 이동 방향이 보인다
- **테마 자금 흐름 히트맵** — 5일 누적 수급을 테마별로 집계
- 구현: `ka10062`(동일순매매순위)와 업종 구성종목을 조합

## 2-2. 시장 폭(Breadth) 지표 — 이미 데이터는 있다

지수만 보면 속는다. 오늘도 코스피 +3.56%인데 **하락 종목이 더 많았다.**

- **등락비율(ADR)** = 상승종목수 / 하락종목수. 20일 이동평균과 함께
- **신고가-신저가 스프레드** — 추세의 건강도
- **일별로 쌓아 추세화** — 지금은 당일 값만 보고 버린다. 매일 저장하면 추세가 보인다
- 저장 비용: 하루 몇백 바이트. 리포트와 함께 `data/breadth/`에 누적

## 2-3. 수급 주체별 "연속성"

하루치 순매수는 노이즈가 많다. **며칠 연속인지**가 신호다.
- 외국인 N일 연속 순매수 종목/업종
- 연기금 vs 투신의 방향이 엇갈리는 구간 (기관 내부 이견 = 변곡 가능성)
- `ka10062` 연속매매현황이 이미 구현돼 있는데 리포트에 안 들어감

## 2-4. 신용·공매도로 보는 과열/바닥

- **신용잔고율 급증 종목** — 반대매매 리스크
- **공매도 비중 급감 + 주가 상승** = 숏커버링 신호
- 개별 종목엔 구현돼 있으나 **시장 전체 집계가 없다**

## 2-5. 관심종목 포트폴리오 뷰

- 관심종목 전체의 **업종/테마 분포** — 내가 한쪽에 쏠려 있는지
- 관심종목 **합산 수익률 추이** — 내 판단이 시장 대비 나았는지
- 이건 "훈련 도구"라는 이 앱의 목적에 가장 직결된다

## 2-6. 과거 리포트 되돌아보기 (Backtest-lite)

리포트를 매일 저장하고 있으니:
- **"1주일 전 체크포인트가 맞았나"** 를 자동으로 대조
- AI에게 "지난주 조간에서 지적한 것들이 어떻게 됐는지 평가해줘" 요청
- 이게 진짜 훈련이다. 예측 → 결과 → 복기 루프

# 3. 수동 테마 (사용자 정의 테마)

## 3-1. 왜 필요한가

키움 테마 분류는 **시장의 현재 관심사를 못 따라간다.**
- 새로 뜨는 테마(예: 온디바이스AI, 로봇, 전력설비)가 없거나 늦게 반영
- 분류가 너무 넓거나(반도체) 너무 좁다(FPCB)
- 사용자가 보는 관점과 다르다

## 3-2. 자료 구조

```
server/data/customThemes.json
[
  {
    "id": "ct_xxx",
    "name": "AI 전력인프라",
    "memo": "데이터센터 전력 수요 수혜",
    "codes": ["103590", "006340", "267260"],
    "color": "#f5c542",
    "createdAt": "..."
  }
]
```

## 3-3. 기능

- 테마 생성/수정/삭제, 종목 검색해서 추가/제거
- **테마 등락률 = 구성종목 등락률의 시가총액 가중평균** (단순평균은 소형주에 휘둘림)
- 테마별 수급 합계 (외국인/기관 5일)
- 테마맵에 키움 테마와 나란히 표시하되 **내 테마는 구분 표시**
- **리포트·AI 요약에 내 테마를 포함** ← 이게 핵심. 내 관점으로 시장을 보게 됨

## 3-4. 편의 기능

- **키움 테마에서 복사해서 시작** — 기존 테마를 불러와 종목을 빼고 더하기
- **관심종목에서 한 번에 만들기**
- CSV 가져오기/내보내기 (캘린더처럼)

# 4. 미국↔한국 테마 연동

## 4-1. 지금 상태

`docs/다음작업_TODO.md`에 매핑 테이블 초안만 있고 미구현.

## 4-2. 설계 (3단계)

### 1단계: 수동 매핑 + 시각화 (바로 가능)
```
server/data/usKrLinks.json
[
  { "us": ["NVDA","AMD","^SOX"], "kr": ["반도체 대표주","HBM"], "label": "반도체" },
  { "us": ["TSLA","LIT"], "kr": ["2차전지"], "label": "전기차·배터리" },
  ...
]
```
- 화면: 왼쪽 미국 등락 / 오른쪽 대응 국내 테마 등락 나란히
- **`^SOX`(필라델피아 반도체지수) 반드시 추가** — 국내 반도체와 상관성 최상

### 2단계: 상관계수 검증 (자동화)
- 미국 티커 일봉 vs 국내 테마 일별 등락률 **60일 상관계수**
- 0.5 미만이면 "연동 약함" 표시하거나 매핑에서 제외
- 하드코딩 매핑이 낡는 문제를 자동으로 잡아냄

### 3단계: 시차 분석 (진짜 가치)
- 미국 t일 등락 → 한국 t+1일 등락 상관 (**하루 시차**가 정상)
- "어젯밤 SOX +3% → 오늘 국내 반도체 테마는 보통 +1.8% 따라감. 오늘은 +0.4%뿐 → **덜 반영됨**"
- 이렇게 **기대 대비 실제**를 보여주면 판단에 직접 쓰인다

## 4-3. 조간 리포트에 넣을 형태

```
[밤사이 미국 → 오늘 볼 것]
SOX +3.2%  → 국내 반도체 (평소 연동 0.72, 기대 +1.8%)
TSLA -2.1% → 2차전지 (연동 0.58, 기대 -1.0%)
```

## 4-4. 주의

- **상관관계는 변한다.** 고정 진리로 표시하지 말고 상관계수를 함께 보여줄 것
- 미국 휴장일 처리
- 참고 지표이지 매매 신호가 아니라는 톤 유지

# 5. 우선순위 제안

| 순위 | 항목 | 이유 |
|---|---|---|
| 1 | **관심종목 시그널 봇** (1-3) | 텔레그램을 쓰는 진짜 이유. 즉시성이 가치 |
| 2 | **수동 테마** (3) | 내 관점으로 시장을 보게 됨. 리포트 품질도 같이 올라감 |
| 3 | **시장 폭 지표 누적** (2-2) | 저장만 시작하면 시간이 자산이 됨. 빨리 시작할수록 좋음 |
| 4 | **미국↔한국 1단계** (4) | 조간 리포트의 핵심 |
| 5 | 대화방 분리 + 인라인 버튼 (1-1, 1-2) | 봇이 묻히지 않게 |
| 6 | 과거 리포트 복기 (2-6) | 데이터가 쌓인 뒤에 의미 있음 |

> **3번(시장 폭 누적)은 지금 당장 저장만이라도 시작하는 걸 권한다.**
> 오늘 안 쌓으면 한 달 뒤에도 추세를 못 본다. 코드는 몇 줄이면 된다.
