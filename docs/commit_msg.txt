웹 리서치를 Gemini 검색 그라운딩으로 — 최대 비용 항목을 700분의 1로.

크레딧 $5 가 하루 만에 비어서 어디로 나갔는지 셌더니 8/14 하루가 $5.64 였고,
입력 토큰 2,201,120 중 1,918,526 이 그날이었다. 그날 발행된 리포트가 8건(정기 3 +
즉시 5)이었는데, 그때는 발행마다 웹 리서치를 새로 돌리는 구조였다.

입력이 컸던 건 우리가 정제를 안 해서가 아니라 Anthropic 서버사이드 web_search 가
검색 결과를 대화에 쌓아 매 턴 재전송하기 때문이다. 그 결과는 우리 손을 안 거치므로
미리 줄일 수도 없다. 그래서 검색 주체를 바꿨다. 실측:

  claude-sonnet-5        입력 107,000 토큰 · 검색 6회       $0.29   / 회
  gemini-3.5-flash-lite  입력     348 토큰 · 출력 849 토큰  $0.0004 / 회

같은 프롬프트에 같은 형식의 답이 나왔다. Google 그라운딩은 검색 결과를 서버에 두고
요약만 돌려주므로 결과가 토큰으로 잡히지 않는다.

- 설정 > AI 모델에 「웹 리서치 (입력 정제)」 용도 추가. 안 고르면 예전 경로 그대로다.
- 하루 상한 4회(RESEARCH_DAILY_LIMIT). 캐시는 "덜 부르게" 하는 장치고 이건 "못 부르게"
  하는 장치다 — 「지금 발행」을 여러 번 누르면 캐시가 만료돼 있어 다시 샌다.
- gemini-2.5-flash 는 목록에 남아 있지만 부르면 404 다("no longer available to new
  users"). 실측으로 확인하고 실제로 도는 모델로 갈아끼웠다. 단가표도 맞췄다.

오늘 공시 (캘린더 최상단).

DART 는 하루 2,000건 넘게 쏟아진다. 다 보는 건 불가능하고 볼 이유도 없다 — 내가 들고
있거나 보고 있는 종목의 공시 한 건이 나머지보다 중요하다. 세 겹으로 거른다.

  1) 코스피·코스닥으로 한정 (corp_cls=Y/K)
  2) 주요사항·발행공시로 한정 (pblntf_ty=B/I) — 정기보고서는 뺀다
  3) 내 종목 / 내 테마 / 그 밖으로 갈라 보여준다

실측으로 226건 → 내 종목·테마 6건이 됐다. 중요도가 아무리 높아도 남의 종목이 내 종목
위에 오지 않는다 — 이 화면의 목적은 "오늘 무슨 공시가 있었나"가 아니라 "내가 볼 게
있나"다. 정정공시는 따로 표시한다(원문과 달라진 부분을 봐야 하므로).
오늘 것이 없으면 직전 영업일로 사흘까지 물러난다 — 장 전이나 휴장일에 "없음"만 뜨면
화면이 죽은 것처럼 보인다.
리포트 프롬프트에도 넣었다. 내 종목 것만이라 토큰이 얼마 안 든다.
