# 미니PC 원격 배포 — 깃발 하나로

메인 PC 에서 `git push` 한 뒤 **미니PC 앞에 앉지 않고** 배포하기 위한 장치다.

## 왜 이렇게 만들었나

미니PC 에 붙는 길을 전부 재 봤다 (2026-09-02).

| 경로 | 상태 |
|---|---|
| Tailscale | ✅ `nucbox-g10` 100.88.182.35 온라인 |
| SSH (22) | ❌ OpenSSH 서버가 안 켜져 있음 |
| WinRM (5985/5986) | ❌ 닫힘 |
| SMB (445) | ✅ 열림 — **인증은 통과** (IPC$ 연결 성공) |
| 관리자 공유 `C$` | ❌ 거부 |

관리자 공유가 막힌 것은 비밀번호 문제가 아니다. 윈도우는 **로컬 계정으로 원격
접속하면 관리자여도 권한을 깎아서** 준다(`LocalAccountTokenFilterPolicy`).
그걸 풀면 원격 실행까지 한 번에 열리지만, 윈도우가 일부러 걸어 둔 보호를 푸는
일이라 택하지 않았다.

대신 **문을 안 열고 쪽지만 주고받는** 방식으로 갔다. 미니PC 가 1분마다 제 폴더를
들여다보다가 깃발이 있으면 스스로 배포한다. 원격 실행 권한이 아예 필요 없다.

## 구조

```
메인 PC                        미니PC
  │                              │
  │  ① 깃발 파일 하나 떨구기      │  ② 1분마다 살펴봄 (예약작업)
  ├─────────────────────────────>│     VNTG DEPLOY WATCH
  │   \\…\vntg-deploy\deploy.flag│        └ deploy-watch.cmd
  │                              │             └ deploy.cmd
  │                              │                (pull → 빌드 → 재시작)
  │  ④ 로그·상태 읽기             │  ③ 결과를 같은 폴더에 씀
  │<─────────────────────────────┤     deploy.log / deploy.status
```

**공유하는 것은 `C:\vntg-deploy` 뿐이다.** 저장소 폴더(`C:\vntg-hts`)는 공유하지
않는다 — 거기엔 `.env`(텔레그램 세션 문자열·API 키)와 `server\data`(되살릴 수
없는 원장)가 들어 있다. 깃발 폴더에 오가는 것은 아래 넷뿐이다.

| 파일 | 누가 쓰나 | 뜻 |
|---|---|---|
| `deploy.flag` | 메인 PC | 「배포해라」. 감시가 **먼저 지우고** 배포한다 |
| `deploy.lock` | 미니PC | 배포 중. 겹쳐 도는 것을 막는다 |
| `deploy.log` | 미니PC | 이번 배포의 전체 출력 + `/api/health` 응답 |
| `deploy.status` | 미니PC | `OK`/`FAIL` + 시각 + 배포된 커밋 해시 |
| `watch.alive` | 미니PC | 감시가 살아 있다는 표시(매분 갱신) |

## 설치 — 미니PC 에서 한 번만

1. 평소처럼 바탕화면 `update.cmd` 를 한 번 더블클릭한다
   (이 스크립트들이 저장소에 내려와야 하므로 이 한 번은 필요하다)
2. `C:\vntg-hts\setup-deploy-watch.cmd` 를 **우클릭 → 관리자 권한으로 실행**
3. 1분 안에 `C:\vntg-deploy\watch.alive` 가 생기면 성공

계정 이름이 `VNTG` 가 아니면 `setup-deploy-watch.cmd` 의 `ACCT` 를 고친다
(실패하면 스크립트가 계정 목록을 찍어 준다).

## 메인 PC 에서 한 번만

미니PC 자격증명을 저장해 둔다. **비밀번호는 이때 사람이 직접 친다.**

```
cmdkey /add:100.88.182.35 /user:100.88.182.35\VNTG /pass
```

## 쓰기

```powershell
# 배포 걸기
New-Item "\\100.88.182.35\vntg-deploy\deploy.flag" -ItemType File -Force

# 결과 보기 (1~4분 뒤)
Get-Content "\\100.88.182.35\vntg-deploy\deploy.status"
Get-Content "\\100.88.182.35\vntg-deploy\deploy.log" -Tail 40
```

## 알아 둘 것

- **실패하면 서비스를 재시작하지 않는다.** 빌드가 깨졌는데 재시작하면 멀쩡히
  돌던 것까지 죽는다. 옛 빌드가 계속 돈다.
- **배포 중에 미니PC 가 꺼지면 `deploy.lock` 이 남는다.** 그러면 그다음부터
  깃발을 떨궈도 아무 일이 안 일어난다. 지우면 된다.
- 깃발을 지우는 것이 배포보다 **먼저**다. 나중에 지우면 실패했을 때 깃발이 남아
  1분마다 같은 실패를 무한히 반복한다.
- 감시 작업은 **로그인해 있을 때만** 돈다(`/RU` 를 안 줬다 — 안 그러면 등록할 때
  비밀번호를 받아야 한다). 미니PC 는 상시 로그인 상태로 HTS 를 굴리므로 문제없다.
