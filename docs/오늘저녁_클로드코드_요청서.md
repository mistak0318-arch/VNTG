## STEP 0. 키 관리 점검 (작업 시작 전)

> 이 프로젝트는 키움 앱키/시크릿, DART 인증키 등 민감한 키를 다룸.
> 코드 작업 전에 먼저 이것부터 정리할 것.

```
이 프로젝트에서 사용하는 모든 API 키/시크릿을 점검해줘.

[대상 키]
- 키움 앱키 (KIWOOM_APP_KEY)
- 키움 시크릿키 (KIWOOM_SECRET_KEY)
- 키움 액세스 토큰 (런타임 발급)
- DART 인증키 (DART_API_KEY)
- (추후) Anthropic API 키 (ANTHROPIC_API_KEY)

[점검 및 수정할 것]
1. 소스코드에 하드코딩된 키가 있는지 전수 검사 → 있으면 .env로 이동
2. .gitignore에 .env가 포함되어 있는지 확인. 없으면 추가
3. 이미 git 히스토리에 커밋된 키가 있는지 확인
   (있으면 알려줘 — 해당 키는 재발급이 필요함)
4. .env.example 생성 (키 이름만, 값은 비워둘 것)
5. 로그에 키나 토큰이 출력되는 곳이 있는지 확인 → 마스킹 처리
6. 프론트엔드로 키가 내려가는 경로가 있는지 확인
   - 클라이언트가 키움/DART API를 직접 호출하는 코드가 있으면
     서버 경유 방식으로 변경할 것
7. 에러 응답에 키나 토큰이 포함되어 나가지 않는지 확인

[코드 작성 규칙]
- 키는 반드시 process.env.XXX 로만 참조
- 키 값을 콘솔, 로그, 주석, 커밋 메시지에 남기지 말 것
- 액세스 토큰도 동일하게 취급 (로그 출력 금지)
```

**내가 직접 해야 할 것 (Claude Code에 시키지 말 것)**
- [ ] `.env` 파일에 실제 키 값 직접 입력
- [ ] 채팅·문서·메모에 키를 붙여넣지 않기
- [ ] 미니 PC로 이전할 때 `.env`는 코드와 별도로 옮기기 (USB 등)
- [ ] 노출 의심되면 즉시 재발급
  - 키움: 개발자센터에서 앱키 재발급
  - DART: opendart.fss.or.kr에서 인증키 재발급

**키별 위험도**

| 키 | 유출 시 위험 |
|---|---|
| 키움 앱키/시크릿 | **높음** — 계좌 조회 가능. 주문 권한까지 열려 있으면 실제 매매 가능 |
| Anthropic API 키 | **높음** — 남이 내 크레딧으로 과금 |
| DART 인증키 | 낮음 — 공개 정보 조회용. 다만 호출 한도를 남이 소진시킬 수 있음 |

## STEP 2. 키움 API 제공 범위 조사

```
시황 대시보드를 만들려고 해. 키움 REST API 문서와 현재 코드베이스를 확인해서
아래 항목들이 제공되는지 조사해줘. 코드는 작성하지 말고 조사 결과만 보고해줘.

각 항목마다 TR명 / 엔드포인트 / 요청 파라미터 / 응답 필드명을 정리해줘.

[시장 집계]
1. 코스피/코스닥 "시장 전체" 투자자별 순매수 집계
   - 종목별 합산이 아니라 시장 단위로 한 번에 주는 TR이 있는지
2. 기관 세부 구분 (금융투자 / 투신 / 연기금 / 사모펀드)이
   분리되어 나오는지, 필드명과 코드값 매핑
3. 선물 투자자별 매매동향 (파생 카테고리에서 별도로 찾아볼 것)

[순위/집계]
4. 종목등락현황 (상한/상승/보합/하락/하한 종목 수 집계)
5. 등락률 순위 (상승/하락/상한가/하한가 종목 리스트)
6. 업종별 등락률
7. 250일 신고가/신저가
8. VI(변동성 완화) 발동 종목 — 실시간 이벤트인지, WebSocket이 필요한지
9. 증시주변자금 (고객예탁금/미수금/신용잔고/선물예수금)

[테마] ★ 중요
10. 키움이 제공하는 종목 섹터/테마 분류 맵을 조회하는 TR이 있는지
    - 이게 업종(화학, 제약 등 KRX 표준) 수준인지,
      테마(정유, 국내상장중국기업, 낙태/피임 등) 수준인지 구분해서 알려줘
    - MTS 화면에 나오는 테마 목록과 일치하는지

[기타]
11. 지수 분봉 데이터 (스파크라인용)
12. **뉴스 조회 TR이 있는지** (종목별 뉴스 / 시장 전체 뉴스)
13. 각 TR의 rate limit (초당/분당 호출 제한)
14. 순위 조회 TR이 시세까지 같이 주는지, 종목코드만 주는지
    (종목코드만 주면 개별 조회가 추가로 필요해서 호출량이 급증함)
```

## STEP 3. 시황 탭 구현

> STEP 2 결과를 받고 나서 진행. 제공 안 되는 항목은 빼고 요청할 것.

```
조사 결과를 바탕으로 "시황" 탭을 신규 구현해줘. 탭 순서에서 맨 앞에 배치.

[화면 구성]
- 국내 지수 4종 (KOSPI / KOSDAQ / 코스피200 / 선물)
  각 카드에 현재가, 전일대비, 등락률, 스파크라인, 외국인/기관/개인 순매수
- 투자자별 수급 상세 (개인/외국인/기관, 기관은 금융투자·투신·연기금·사모펀드로 세분화)
- 글로벌 (달러/원, WTI, US30/500/Tech100/2000, VIX, 미국 10년·30년물, 비트코인)
- 종목등락현황 (상한/상승/보합/하락/하한 × 코스피/코스닥)
- 증시주변자금
- 등락률 순위 / 업종 / 테마 / 250일 신고저가 / VI

[디자인] ★
- 프로젝트에 넣어둔 시황탭_목업.html의 레이아웃과 스타일을 그대로 따를 것
- 모바일: 서브탭 [요약][수급][순위]으로 분리
- 태블릿(700px~): 서브탭 없이 2열
- PC(1100px~): 3열 대시보드, 수급 패널은 2칸
- 다크 테마, 숫자는 tabular-nums, 수급은 중앙 기준 좌우 막대
- 상승/순매수 빨강, 하락/순매도 파랑

[기술 요구사항]
- 서버가 키움 API를 호출하고 결과를 캐싱, 클라이언트는 캐시만 조회
  (클라이언트가 키움을 직접 호출하지 않게 할 것 — 키 노출 + rate limit 방지)
- 캐시 TTL은 섹션별로 차등 (지수 짧게, 순위/업종 길게, 주변자금은 1일)
- 종목 클릭 시 기존 종목 정보 화면으로 연결
- 장 시간 외(장전/장후/휴장일) 처리, 상단에 장 상태 배지
- 각 카드에 마지막 갱신 시각 표시
- 스켈레톤 로딩, 섹션별 독립 에러 처리
```

## STEP 5. 테마 처리

> STEP 2의 10번 결과에 따라 분기

**키움에서 테마 분류가 나오는 경우**
```
키움 섹터/테마 분류 TR을 사용해서 테마별 등락률 상위/하위를 구현해줘.
테마 클릭 시 구성 종목 리스트를 보여주고, 종목 클릭 시 종목 정보로 연결.
```

**키움에 없는 경우 (대안)**
```
테마 분류가 키움 API에 없으니 아래 구조로 구현해줘.

- 하루 1회 배치로 네이버 금융 등에서 "테마 → 구성 종목 매핑"만 크롤링
  → theme_map.json 으로 저장
- 시세는 키움 API로 조회, 크롤링은 매핑 테이블 용도로만 사용
- 테마 등락률은 구성 종목 등락률의 단순평균으로 계산
- 크롤링 실패 시 이전 매핑 파일을 유지 (fallback) — 시세는 계속 동작하게
- robots.txt 확인, 요청 간격 1초 이상, User-Agent 명시
```

## STEP 6. 뉴스 탭 구현

```
"뉴스" 탭을 신규로 만들어줘.

[구성]
- 상단에 종목 검색창
- 검색 안 했을 때: 증권 주요뉴스 피드
- 종목 검색 시: 관련 뉴스 + 공시 + 종목 기본 정보를 병렬로 조회해서 표시

[데이터 소스 — API 우선]
1. 공시: DART OpenAPI (금감원 공식, https://opendart.fss.or.kr)
   - 인증키는 .env의 DART_API_KEY에 있음. process.env로만 참조하고
     소스코드나 로그에 키 값을 남기지 말 것
   - DART는 자체 고유번호(corp_code)를 쓰므로 종목코드 ↔ corp_code
     매핑 테이블을 전체 다운로드해서 캐싱해둘 것
2. 뉴스: 먼저 키움 REST API에 뉴스 조회 TR이 있는지 확인해줘.
   - 있으면 그걸 사용
   - 없으면 네이버 검색 API(공식) 사용
   - 그것도 안 되면 마지막 수단으로
     https://m.stock.naver.com/investment/news/mainnews 크롤링
     (robots.txt 확인, 요청 간격 1초 이상, User-Agent 명시)

[요구사항]
- 뉴스 본문 전문은 표시하지 말 것 (저작권)
  → 제목 / 언론사 / 시각 / 원문 링크만
- 공시는 보고서명 / 제출인 / 접수일 / DART 원문 링크
- 검색마다 외부 호출하지 말고 캐싱할 것
- 종목명이 중복되면 후보 리스트를 보여주고 선택하게
- 디자인은 시황 탭과 동일한 토큰 사용 (다크 테마, 색상 규칙)
- 모바일: 뉴스/공시 탭 전환 / PC: 좌우 2열

[기존 종목 상세 화면에도 연동] ★
이미 구현되어 있는 "종목 클릭 → 종목 정보 표시" 화면에
뉴스 / 공시 버튼(또는 탭)을 추가해줘.

- 종목 상세 화면에서 바로 그 종목의 뉴스와 공시를 볼 수 있게 할 것
- 뉴스 탭에서 검색했을 때와 동일한 데이터·동일한 표시 형식을 쓸 것
  → 뉴스 조회 / 공시 조회 로직을 공통 모듈로 분리해서
    뉴스 탭과 종목 상세 화면이 같은 코드를 재사용하게 설계할 것
    (중복 구현하지 말 것)
- 종목 상세에서 넘어온 경우와 뉴스 탭에서 검색한 경우 모두
  같은 캐시를 공유하게 해서 중복 호출 방지
- 기본 정보 / 차트 / 뉴스 / 공시 형태의 탭 구성을 제안해줘
  (기존 화면 구조를 먼저 보고, 어떻게 넣는 게 자연스러운지 알려줘)
```

## STEP 7. 로그인 (Google OTP)

```
웹 UI에 TOTP 기반 로그인을 추가해줘. otplib + qrcode 사용.

- 최초 1회: 시크릿 생성 → QR 렌더링 → Google Authenticator 등록
- 시크릿은 .env에 저장, 파일 권한 600
- 로그인: 6자리 입력 → authenticator.verify() → 세션 쿠키 발급
- express-rate-limit으로 5회 실패 시 잠금
- 이미 사용된 코드는 30초 창 안에 재사용 불가 (replay 방지)
- 로그인 안 된 상태에서는 모든 API 엔드포인트 차단
```

## STEP 8. 미니 PC 이전 준비

```
이 프로젝트를 다른 PC(Windows 11)로 옮겨서 24시간 구동하려고 해.
아래를 준비해줘.

1. README에 설치/실행 절차 정리 (Node 버전, 필요한 패키지, .env 항목 목록)
2. .env.example 파일 생성 (실제 키값은 제외)
3. pm2 설정 파일 작성
   - 자동 재시작
   - max_memory_restart 512M (메모리 누수 대비)
   - 로그 로테이션
4. Windows 서비스로 등록하는 방법 안내 (pm2-windows-startup 또는 NSSM)
5. 헬스체크 엔드포인트 추가 (/health)
   - 서버 상태 (uptime, 메모리 사용량)
   - 키움 액세스 토큰 유효성 및 만료 시각
   - **현재 공인 IP** (키움 API에 IP 접근제한이 걸려 있어서 중요)
   - 각 외부 API(키움/DART/Yahoo 등) 마지막 성공 호출 시각
   - 캐시 상태 (섹션별 마지막 갱신 시각)

6. IP 변경 감지
   - 서버가 주기적으로 공인 IP를 확인해서 이전 값과 다르면 로그에 경고
   - 키움 API가 IP 관련 에러를 반환하면 그 사유를 명확히 구분해서 로깅
     (토큰 만료인지, IP 차단인지 헷갈리지 않게)
   - 배경: 키움 앱키에 IP 접근제한이 설정되어 있고, 가정용 인터넷은
     유동 IP라 공유기 재부팅이나 통신사 갱신 시 IP가 바뀌면 API가 막힘.
     이때 원인을 빨리 파악할 수 있어야 함
```
